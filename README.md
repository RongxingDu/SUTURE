# SUTURE

**SUTURE** — **Su**ffix-replayed **T**race-localized **U**pdates with
**R**untime-adaptive **E**xecution — is an experimental framework for reliable
and efficient optimization of API-based LLM agentic workflows.

The method follows a simple **repair, then route** principle:

1. repair what the workflow does using failure traces, anchor-local edits, and
   replay validation; then
2. freeze the repaired workflow and calibrate how it executes using a
   lightweight gate plus an LLM scheduler for borderline decisions.

The Python import package and the original `awf-*` commands remain available as
compatibility interfaces. New documentation and command aliases use the
SUTURE name.

See [docs/SUTURE_METHOD.md](docs/SUTURE_METHOD.md) for the full algorithm,
objectives, runtime policy, and research-scope boundaries.

## Install

```bash
python -m venv .venv
.venv/bin/pip install -e '.[dev]'
```

Set the API key expected by the configured OpenAI-compatible endpoint:

```bash
export OPENAI_API_KEY=...
```

Configuration inheritance is recursive. API keys are redacted from saved
experiment results.

## Run

See [experiments/README.md](experiments/README.md) for the complete command
tutorial: the one-click optimize-and-test pipeline script, the manual
`suture-optimize` / `suture-test` entrypoints, and the full configuration
parameter reference.

One-click pipeline (optimize then official held-out test):

```bash
bash experiments/scripts/run_optimize_and_test.sh \
  --config experiments/configs/math_aliyun_qwen35_full.yaml \
  --benchmark math \
  --data /path/to/benchmark.jsonl \
  --api-key "$ALIYUN_API_KEY"
```

Manual optimization:

```bash
suture-optimize \
  --config experiments/configs/math.yaml \
  --benchmark math \
  --data /path/to/gsm8k.jsonl
```

The optimizer creates reproducible optimization/validation/test splits,
validates the initial workflow as round 0, applies validation-based early
stopping, and writes a manifest binding the ordered dataset, exact split
indices, scientific config, and validation-selected checkpoint. It does
**not** evaluate the held-out test split.

After optimization, run the official test once with the exact same config,
ordered dataset, benchmark, and execution mode:

```bash
suture-test \
  --results experiments/results/math/results.json \
  --config experiments/configs/math.yaml \
  --benchmark math \
  --data /path/to/gsm8k.jsonl
```

`suture-test` rejects manifest mismatches and a second official evaluation, then
atomically records `test_metrics` and `test_evaluated_at` in `results.json`.

Code generated by an LLM is not executed by default. Production evaluation
must inject a `CodeRunner` backed by a real container or VM sandbox. The
`--allow-local-code-execution` option enables a resource-limited subprocess
runner only for trusted fixtures; it does **not** isolate the filesystem or
network. The code CLI otherwise refuses to start unless
`--allow-zero-hard-reward` explicitly acknowledges that hard reward will be
unavailable.

Counterfactual reruns likewise default to tools explicitly marked or
allowlisted as safe. Tools with side effects require a real sandbox or a
transaction adapter that can isolate and roll back their effects; do not
allowlist them as ordinary replay-safe tools.

Executor timeouts stop awaiting a timed-out step, but Python cannot forcibly
terminate a synchronous function already running in a worker thread.
Side-effecting production tools therefore need cooperative/async cancellation
or process/container isolation with their own timeout and rollback semantics.

## Method overview

SUTURE optimizes two different objects in sequence. The workflow is learned
first while execution scheduling is frozen; scheduler calibration begins only
after the workflow has been fixed. This avoids attributing one stochastic
change simultaneously to workflow content and runtime routing.

### Stage 1: trace-localized workflow repair

An optimization round consumes current-version failures and a bounded sample
of successful regression guards. An LLM localizer ranks suspicious executed
nodes across the failure traces. Candidate generation then searches prompt,
operator, graph-path (`block` internally), and optional multi-level edits from
the least to the most invasive scope.

Each candidate is compared with the incumbent on paired rows. When the trace
contains a valid checkpoint before the first changed node, SUTURE restores the
unchanged prefix and executes only the candidate suffix. A repair is eligible
only after satisfying the configured failure-coverage gate and the protected
success non-regression gate. In the conservative protocol, the first scope
containing a valid repair stops broader search.

Hard reward utility and candidate gain are:

```text
R = R_hard + alpha * R_process
U = R_hard
G = delta_U - lambda_cost * (C_exec_candidate - C_exec_incumbent)
    - mu_edit * D_edit
```

`R` is retained as a process-quality diagnostic. `C_exec` is the recorded
input/output-token count; a reduction therefore contributes positively to
`G`. Latency, API cost, and runtime complexity remain separate diagnostics or
efficiency-anchor signals and do not alter `U`. In the legacy gain-driven
path, candidate edits are accepted only when:

```text
G > epsilon_stat
```

Failure-repair updates use the stricter suffix-replay
correctness gate described below; `G` is then only a tie-break after valid
repairs have been established.

The scheduler and optimizer both use API clients; no local model training or
inference is assumed.

### Stage 2: calibrated runtime scheduling

After the workflow is frozen, the cascade scheduler evaluates each available
artifact using four label-free runtime features: specification adherence,
lightweight artifact quality, agreement with prior artifacts, and historical
node reliability. Its calibrated policy has three outcomes:

```text
low score                 -> follow the frozen workflow template
borderline/promising      -> ask the compact LLM scheduler
high-confidence terminal -> early exit
```

The LLM scheduler may continue, verify, reroute, repair, fall back, or exit,
subject to workflow dependencies and the configured deviation policy. Gate
weights and thresholds are selected on validation traces with hard correctness
as a constraint and token/latency savings as secondary objectives. The
calibrated scheduler is deployed only if a separate real-execution validation
audit confirms both hard non-regression and a strict efficiency improvement.

The complete two-stage protocol is enabled by setting
`scheduler.scheduler_type: cascade`, `scheduler.calibration_enabled: true`,
and a `scheduler_calibration_round` after the workflow-optimization rounds.
See `experiments/configs/suture_math40.yaml` for the
research configuration.

## Research modes and legacy components

The repair-only ablation uses `optimizer.workflow_content_only: true` and a
fixed/graph scheduler. It retains suffix replay as the correctness gate while
disabling the historical query-selective update and high-cost-success trigger.

The former inner-v2/outer-layer knobs are retained in the schema for historical
ablation reproducibility. They become active only in an explicit legacy run
with `workflow_content_only: false`:

```yaml
optimizer:
  workflow_content_only: false  # explicit legacy outer-layer ablation
  hard_success_threshold: 1.0
  min_success_guards: 1
  efficiency_optimization_enabled: true
  efficiency_anchor_fraction: 0.2
  efficiency_min_relative_cost: 1.25
  efficiency_max_anchors: 1
  candidate_archive_size: 3
  exploration_budget: 1
```

Selective Counterfactual Workflow Update (S-CWU) is retained only as a legacy
ablation. It is not the SUTURE scheduler: S-CWU learns a query-level gate tied
to one patch, whereas SUTURE freezes the repaired workflow and calibrates a
separate artifact-aware cascade execution policy.

GPQA, MMLU, and SciCode pilot configs are also included. Install SciCode's
scientific evaluator dependencies with `pip install -e '.[scicode]'`; SciCode
requires the official `test_data.h5` plus the explicit bubblewrap execution
flag. GPQA/MMLU share the minimal one-call multiple-choice workflow.

Ignored local result directories may contain historical S-CWU pilot reports;
they are not part of the versioned SUTURE method specification.
